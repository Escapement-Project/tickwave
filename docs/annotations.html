tickwave sidecar annotations, version 1

Annotations mark spans and points on a recording: a transfer, an acknowledge, a misread, a stretched clock period. They live beside the recording in text files, so they diff, take hand edits, and regenerate without touching the capture. Page text cites an annotation by its id.

Status: draft, with the recording format.

Files#

A recording rec.tickwave has one hand-written TOML file, rec.annotations.toml. A program that generates annotations, such as a protocol decoder, writes its own JSON Lines file, which the TOML file includes: rec.wire_swd.jsonl. An included file sits beside the hand-written one and is named on its own, without a directory. A generator rewrites its file whole on each run. It may start the hand-written file when there is none, and never writes it after that. From then on only tickwave's editor edits it, and it keeps the file's comments, order and layout, so a rerun cannot touch a hand edit. A script that re-pins a sidecar to a reconverted recording may rewrite recording_id, and nothing else.

A generator runs after the recording is converted. It reads the recording's id from tickwave info --json (header.content_id).

The hand-written file#

format = "tickwave-annotations/1"
recording = "rec.tickwave"               # optional; checked against the file name when known
recording_id = "blake3:4f2a…"            # the recording's content id
include = ["rec.wire_swd.jsonl"]         # generator files, beside this one

[[annotation]]
id = "read-ack-check"
start = "317.85882 ms"
end = "317.85891 ms"
channels = ["SWCLK", "SWDIO"]
label = "The 12-cycle period before read data"
kind = "period"
measure = { channel = "SWCLK", what = "rate" }

[[annotation]]
id = "first-misread"
ref = "wire_swd/misread/412093311"
label = "NXP's firmware misreads at 25 MHz"

A generator's file#

The first line names the generator. Each later line is one annotation. Blank lines are skipped.

{"format": "tickwave-annotations/1", "source": "wire_swd", "version": "9f3c2e1", "recording_id": "blake3:4f2a…"}
{"id": "misread/412093311", "kind": "misread", "start": 412093311, "end": 412094105, "channels": ["SWDIO"], "label": "parity wrong"}

source is the generator's name. It is not empty and holds no whitespace, / or \: tickwave names the generator's file after it, rec.<source>.jsonl, beside the recording. version is optional: the generator's own commit or hash, for provenance. role is optional too: the paint roles the generator's lines paint with, each a table as the hand-written file's [[role]] gives one (below).

{"format": "tickwave-annotations/1", "source": "wire_swd", "recording_id": "blake3:4f2a…", "role": [{"name": "probe", "label": "probe drives"}, {"name": "target", "label": "target drives", "weight": 1}]}

Fields#

Field Meaning
id Hand-written: any name without whitespace or /. Generated: the full id is <source>/<id>.
start, end Times. end is absent for a point.
channels Channel names. Absent or empty means every channel.
label Short text shown with the annotation.
kind A free word (transfer, misread, stall). Styling and filtering key on it.
text Longer text, shown in an inset's caption.
paint A role the sidecar declares (below), such as probe: the annotation's channels draw over its span in the role's look.
measure {channel, what}: the inset shows a measure taken from the channel's edges inside the span (below). The channel must be digital, and the annotation a span.
values Figures the annotation states, by name, each a decimal and its unit (below).
ref Hand-written only: the full id of a generated annotation. This one takes its span and channels, and any field it leaves out.

A file may hold no other fields, measure's included: a misspelt one is an error, not ignored. A key stated twice in any object of an annotation, its measure and values included, is an error too, whatever the file's version. A later minor version can add fields (see Versions).

Roles#

A paint role says who drives a line, or anything else a page colours a stretch of a channel by. The sidecar declares each role it paints with: the hand-written file in [[role]] tables, and a generator in its file's first line, as role.

[[role]]
name = "neither"
label = "neither drives"
colour = ["#8a8a8a", "#5c5c5c"]
dash = [2, 1]
Field Meaning
name What a paint names. Lower-case letters, digits and _, starting with a letter, at most 32 bytes.
label What a key and a readout say for the role, at most 200 bytes. The name where it is left out.
colour "#rrggbb" for both faces, or a [day, night] pair of them.
weight CSS pixels added to the trace's line weight, from 0 to 4. 0 where it is left out.
dash The role's dash and gap lengths, in pairs: at most 8 numbers, each from 0 to 64, together at least 1. Each is a number of the role's line widths, its weight included. A solid line where it is left out.

A role takes no other field. A file declares at most 64 roles, and so do a sidecar's files between them. A file that declares more is one problem, and its roles past the 64th are not read.

A paint names a declared role. The check reports one that names no declared role, once for each name, where it is first used. A reader that shows such a sidecar keeps the annotation, draws its channels as if it painted nothing, and keys nothing for it.

Roles keep the order they are declared in: the hand-written file's, then each generator's, in the order include lists the files. One name may be declared in several files, alike: each field is compared once its default is filled in, a label left out being the name, a weight left out 0, and one colour being the pair of it. A colour or a dash left out equals only one left out. A name declared differently in two files is a problem. A name declared alike again keeps the place it first took. A file that declares one name twice is a problem.

Each field of a role's look comes from the first of these that gives it:

  1. The host: the page's --tickwave-role-<name>, -weight and -dash (web/README.md, "Styling"), or an egui host's Palette::roles. A host's weight or dash outside the bounds a declaration's is held to is left to the declaration, and a host can make a dashed role solid.
  2. The role's declaration.
  3. For the colour alone, the role's place in the order of declarations: the first role takes the trace's colour, and the rest ink. A role neither gives a dash is solid.

A declared colour takes the host's face: its day colour by day, its night colour by night.

Where several annotations paint a channel at a tick, the latest in sidecar order draws it. A dash runs on along a painted stretch from where the stretch starts, across the line's edges, and starts again after a gap in the data.

The roles travel with the recording when it is bundled, in the hand-written file and the generators' first lines. A recording that a writer finishes bundles each generator's roles in its file's first line. One repaired after it was cut off before it finished keeps none of them: the writer holds them until it finishes. Nor does a recording read from a writer's snapshot as it is written have them.

The stored view#

The hand-written file may store how a view of the recording starts, in a [view] table. A page or a host that says how to show the recording wins over it.

[view]
channels = ["SWDIO", "SWCLK"]
start = "377.09 ms"
end = "377.25 ms"
colour = ["#d9480f", "#ff8a50"]
Field Meaning
channels The channels a view shows, in this order. Every channel where it is left out.
start, end The span a view shows first: times, as annotations' are. The capture's start and end where they are left out.
colour The trace's colour, "#rrggbb" or a [day, night] pair, under the page's series colour. Ink where it is left out.

Each channel is the recording's, and named once; channels lists one at least. The span lies in the capture and ends after it starts. The table takes no other field.

Measures#

measure takes the channel's edges at ticks in [start, end): an edge at end is outside. It shows no more digits than its ticks carry. A span meant to measure from one edge to another starts at the first edge's tick and ends one tick past the last.

  • rate and period: the running clock. Its periods run from one rising edge to the next, so a span needs at least two rising edges. Sort the span's n periods as p[0..n). Take Q1 = p[⌊(n − 1)/4⌋], Q3 = p[⌈3(n − 1)/4⌉], and IQR = Q3 − Q1, but at least one tick. Keep the periods within [Q1 − 1.5 IQR, Q3 + 1.5 IQR]: Tukey's fences. The measure is the mean of the kept periods, as a rate or a period, and the inset says how many it kept ("mean of 31 of 32 periods"). The fences keep a clock's edge jitter and its quantisation, such as 26 and 27 ns for a 26.67 ns clock. They drop pauses, and a long period that occurs in fewer than a quarter of the periods, such as a slow acknowledge check or a stretched cycle.
  • duration: the time from the channel's first edge in the span to its last, of either polarity. A span needs at least two edges.

Values#

values holds the figures an annotation states, for a page's charts and tables to read. A decoder that measures a session writes them beside its label:

[[annotation]]
id = "session-50"
ref = "wire_swd/session/377858886"
values = { asked = "50 MHz", read_data = "37.5 MHz", write_data = "49.9 MHz" }

In a generator's file the same is "values": {"asked": "50 MHz", ...}. A name is lower-case letters, digits and _, starting with a letter. A value is a decimal, then one space and a unit where it has one: a count, such as a marker's number, has none. It is a string, so "81.0 KiB/s" keeps its last digit. tickwave never converts or rounds a value. A page compares units as text, so micro is always µ (U+00B5 MICRO SIGN), as in times, and never the Greek letter mu (U+03BC).

Times#

A time is either a whole number of ticks from the capture's start, as a JSON integer (digits with an optional -, no fraction or exponent, so not 12.0), or a string holding a decimal and a unit. The decimal is digits with at most one . among them and at least one digit, such as 12, 12.5, .5 or 12., with an optional - or + before it. The unit is s, ms, us, µs, ns or ps, after the decimal with or without whitespace between, and whitespace around the whole is ignored, whitespace being any character Unicode's White_Space property holds: "12 ms", "12ms" and " 0.012 s " are one time. An exponent, digits grouped with spaces, or a decimal without a unit is an error. A decimal converts to ticks exactly, without floating point, and rounds to the nearest tick, halves away from zero. A time still lies in 0..2^53 ticks once converted.

Ids stay stable#

Page text cites ids, so they must survive a decoder's rerun. A generator derives each id from the recording, not from the run: its kind and start tick, as misread/412093311, not a counter. A hand-written ref gives a generated annotation a name that reads well in prose.

Order#

Annotations keep sidecar order: the hand-written file's, in its order, then each included file's, in the order include lists the files, line by line. Order carries meaning: a view steps through the kind of the first annotation unless it was opened at another, so an author lists first an annotation of the kind a page steps through.

Resolved annotations#

tickwave annotations check --json prints the annotations resolved, in sidecar order, and the browser's decoder hands the page the same. Each has its full id, source (the generator's name; null for a hand-written one), start and end in ticks, and the fields above. An alias keeps ref, the full id of the generated annotation it names, so a page can tell the two apart. A reader that leaves out a generated annotation leaves out an alias of it too, and says so: a ref resolves only to an annotation the reader keeps.

Checks#

tickwave annotations check rec.tickwave rec.annotations.toml reports every problem it finds, then exits non-zero if there was any. A page's build runs it, so a decoder rerun that drops an annotation the prose cites breaks the build instead of the page. It checks that:

  • both files declare format tickwave-annotations/1, or a later minor version of it (see Versions), and their recording_id matches the recording;
  • recording, if given, names the recording's file;
  • every included file is named without a directory, is provided, and every provided file is included;
  • each generator's name is one the rule above allows;
  • ids are unique, hand-written ids hold no /, and every ref names a generated annotation;
  • every channel exists, a point and a span's start lie in 0..length, and a span's end is not before its start and not past length;
  • every measure names a digital channel, or one of a kind this version doesn't know, which may have edges; a known measure; and sits on a span;
  • every value is a decimal, with one space and a unit where it has one, under a name of lower-case letters, digits and _;
  • each role declaration holds to the rules above, no name is declared twice in a file or differently in two, and no file declares more than 64 roles, nor the files between them;
  • every paint names a declared role;
  • a [view] table holds to the rules above.

Versions#

A file's format names its version: tickwave-annotations/1 is version 1, minor version 0, and tickwave-annotations/1.<n> is minor version n. A minor version adds what a reader of an earlier one can leave out and still read everything else as the file means it: top-level keys of the hand-written file or of a generator's first line, fields of an annotation, of a role, of measure and of the [view] table, and values of measure's what. In a file of a later minor version than it knows, a reader leaves out each such key it doesn't know, and each measure whose what it doesn't know, says which in a note that is not a problem, and keeps the annotation, role or view they were in. In a file of its own minor version or an earlier one, a key it doesn't know is an error, as everywhere else in these files. Any other version is another format, which check refuses.

A tool that writes these files again carries what it doesn't know rather than leaving it out. A re-cut and repair carry an annotation's keys and measures they don't know, whatever its file's version, and name them, since a generator's first line, which says its version, may reach them after its annotations do (FORMAT.md, "Annotations"). Repair writes a first line of its own version for a generator whose first line was lost with the cut, so a reader of that version then counts the keys it carried as errors. A merge reads each generator's first line before its lines, and carries what it doesn't know only from a file of a later minor version than its own. Each still leaves out, and names, a line that breaks a rule on a key it knows.

Bundling#

tickwave bundle rec.tickwave rec.annotations.toml -o shared.tickwave checks the sidecar, then writes a copy of the recording with the sidecar's files in it, for a single-file share: the hand-written file and each generator file's first line in its annotation bundle, and each generator file's other lines in annotation parts (FORMAT.md, "Annotations"). The content id stays the same. The roles and the stored view are in the bundle, so a reader has them before it reads any part.

Merging#

tickwave merge carries each input's generated annotations into the merged recording: the generator files it holds, joined from its annotation bundle and annotation parts, or, where it has none, those its sidecar beside it includes. They are bundled again under the merged recording's id. Each time moves with its input as its input's sources do (FORMAT.md, "Sources"): a time x of the input's lies at the input's move plus floor(x × s × R / R_input) on the merged recording's axis, s the input's stretch and R / R_input the merged rate over the input's, and is written in its ticks. Inputs go in the order given. A generator whose name an earlier input's generator took is renamed <stem>-<name>, where <stem> is the input's file name without its extension, with any whitespace written as _. A second clash takes <stem>-2-<name>, and so on. The full ids of its annotations change with it, and so does the source its file's first line names, so a tool that looks for its own generator's file by name finds only the first input's.

An annotation whose times move outside the merged recording is left out: a span that ends at or before its start, or anything that starts at or past its end. A span that reaches over either end is cut there. A line that doesn't read is left out too, and so is one that breaks a rule above for a generator's line. The merge counts each of these.

Channel names in channels and measure follow the names the merge gives. A channel the merge leaves out is dropped from channels, and an annotation left with none is left out. A measure on a channel left out is dropped. An annotation without channels, or with an empty list, which meant every channel of its recording, names that input's channels.

Each carried generator's file keeps its first line as it was: its version, version, the roles it declares and any other key, but for source, renamed as above, and recording_id, the merged recording's. Two inputs whose generators declare one name differently, or a declaration that breaks a rule above, stop the merge: the merged sidecar would fail its check.

A hand-written file's annotations are not carried, since their times are the input's. The merge says how many it left out. Its roles and its stored view are not carried either.
